STM32CubeMX is ST's graphical initialisation code generator. It's been part of my workflow since I started with the STM32 family — you click pins, configure peripherals, and it spits out a project ready to compile. For the first few years, this felt like a superpower.

## The problem with generated code

The issue isn't that the generated code is wrong. It's usually correct, and Cube does a reasonable job of handling clock trees and DMA conflicts. The problem is what it teaches you — or rather, what it doesn't. Engineers who only ever work with Cube-generated projects often don't understand why peripherals are initialised in a particular order, what the HAL abstraction is hiding, or how to debug when things go wrong below the HAL layer.

The bigger practical issue is the regeneration story. Any time you add a peripheral or change a pin, you regenerate — and any custom code in protected regions gets at best awkward and at worst trampled. In a team environment this creates merge conflicts and a maintenance burden that accumulates fast.

## What I use instead

For new projects I write peripheral initialisation by hand against the reference manual, using the LL (Low-Layer) drivers or direct register access depending on how performance-critical the path is. This takes longer at the start but the resulting code is smaller, easier to read, and doesn't carry the HAL's defensive overhead. More importantly, I understand every line of it.

I still use CubeMX for one thing: checking my clock tree. The clock configuration UI is genuinely excellent and saves mental arithmetic. I just don't click Generate Code at the end.

## What to do with existing Cube projects

If you've inherited a CubeMX project, I wouldn't rip it out. The HAL isn't bad — it's just a tradeoff. The better path is understanding what the generated code is doing and extending it carefully, rather than regenerating over your changes.

For new silicon bring-up on an unfamiliar peripheral, I'll still sometimes generate a Cube project once to read the initialisation order — then rewrite it by hand for the production codebase.
